# 《几何学》项目工作流程

本文件管理编辑、核验、资料维护、工作记录与版本操作。共同适用的规则效力见[总则](写作规范.md#总则)；正文质量、术语、排版与书目分别由同目录对应文件主管。

## 1. 开始任务与编辑

| 规则 | 原因 |
|---|---|
| 开始时查看工作区已有修改、目标纲要、相邻 TeX 源码和相关规范，先确认本轮范围。 | 现有修改和数学上下文可能影响任务，先确认可避免覆盖工作或割裂论证。 |
| 有 TeX 源码时优先读源码，PDF 用于成品与具体版面核验。 | PDF 不能完整呈现注释、标签、输入链和证明安排。 |
| 区分评估、审稿与授权修改；在已有写作授权内直接处理常规修改，已明确授权的范围不重复询问。 | 评估本身不授予改稿权限，而重复确认已经确定的事项不能推进工作。 |
| 改变数学范围、跨章编排、选读边界或主要证明位置时，先说明具体影响；作者已明确要求的调整直接落实。 | 这些变动会改变教学承诺和阅读条件，需要由实际写作目标决定。 |
| 编辑时落实目标对象、陈述、证明、例子与习题，核对基域、维数、正则性及实际所需条件。 | 扩写提纲或单句不能保证证明链和教学任务完整。 |
| 新术语与符号先查《术语规范》，新标签与排版查《格式规范》；改名时检索五卷受影响用法。 | 名称、符号和标签会传播到正文、目录、索引及跨卷引用。 |
| 修改后只同步确有变化的纲要、输入链、引用和当前完成状态。 | 必要同步能保证导航准确；无变化的项目不应制造重复维护。 |
| 新增或修改代码只在语法和逻辑结构需要时换行，嵌套层级保持一致；TeX 与 PowerShell 使用 Tab 缩进，Python 等对缩进敏感的语言遵守文件既有的合法缩进，不混用制表符与空格。不为凑行宽拆散短语句，也不把独立操作挤到同一行。 | 简洁而稳定的结构便于阅读、修改和比较差异；语法敏感文件中的任意缩进替换可能改变含义或使脚本无法运行。 |

## 2. 审稿意见与数学疑点

| 规则 | 原因 |
|---|---|
| 将意见逐条对照当前源码，先判断是否仍适用，不机械照抄旧行号或前作的处理。 | 意见可能依据旧版本，同名对象也可能使用不同假设。 |
| 数学修改追踪定义、被调用结果和后续使用，不只修被指出的一句。 | 局部条件变化可能改变整条证明链。 |
| 影响当前任务且无法判断的数学或作者取舍，提出具体问题；能够独立推进的部分继续完成。 | 明确问题可避免猜测补齐，也不必让局部疑点阻塞无关工作。 |
| 未解决的疑点保留真实状态；必要时在已有相关记录中保留问题、位置和下一步依据，不另写每次调查的流水。 | 下次需要接续问题本身和判断依据，而非重放全部操作。 |
| 只有正式审核或明确结论发生变化时才更新相应审核字段；普通自检和成功编译不增加正式审核轮次。 | 排版、自检与数学审核回答不同问题，混写会误导后续安排。 |

## 3. 资料、书目与跨卷调用

| 规则 | 原因 |
|---|---|
| 新资料先确认身份、版本、实际取得和核读范围；正式入库与正文引文按《书目维护注意事项》执行。 | 下载、著录真实、已经阅读和支持当前论断是不同事实。 |
| 确有后续用途的资料在[参考资料目录](../工作记录/参考资料目录.md)登记来源、确切版本、可找到的路径或标识、实读范围与用途；取得日期仅在辨别快照或来源时保留。 | 这些信息用于找回所读版本、避免重复查找和核对引用；无辨识作用的信息不必反复登记。 |
| 只有需要区分同名文件、修订版本或不稳定下载时才保留必要的文件身份、日期或哈希，不为每次编译保存一套校验清单。 | 校验信息应解决版本识别问题，重复记录可重建产物不能方便后续工作。 |
| 同一资料供多卷使用时不重复复制；版本改变先核对差异，不静默替换引用依据。 | 版本差异会影响分页、陈述和证明，重复副本则容易漂移。 |
| 第三方原文件放在本地 `参考文献原文件/`，与源码分开保存并保持不提交。 | 使用资料不自动取得重新分发全文的授权。 |
| 实际跨卷调用在[跨卷引用表](../工作记录/跨卷引用表.md)登记引用处、目标、稳定标签、所用内容、条件及证明状态；纲要已有的未来安排不整份重复抄入。 | 五卷独立成书，需要识别实际依赖；重复规划会产生两个需要同步的版本。 |
| 已证调用、前瞻陈述和计划位置按实际区分；目标未写成时不因目录或标签存在而认定已证明。 | 后续写作需要知道哪些结论可用，不能用未来计划填补当前证明。 |

## 4. 构建与核验

| 规则 | 原因 |
|---|---|
| 初稿阶段以完成正文、证明、例子与习题为主，压低审查时间占比；保留写作所需的数学自检，不另行展开全面审读或格式精修。 | 作者已安排后续至少两轮外部审核；当前应优先推进内容，避免提前重复审核与排版工作。 |
| 使用现有 TeX Live 和项目编译入口；只改一卷正文时构建该卷，改变共享样式或编译逻辑时构建五卷。 | 核验范围应覆盖实际影响，避免漏检或无谓重编。 |
| 只改说明与规范、未改变 TeX 或编译规则时不重编 PDF。 | 此类文档修改不改变现有排版产物。 |
| 每卷缓存写入 `tmp/build/BookN/`，不清理其他任务正在使用的缓存；成功后才更新对应 PDF。 | 缓存隔离可避免并行任务互相污染，也防止失败产物冒充新成品。 |
| 失败时先查本次日志的首个有效错误，优先修复现有工具和配置。 | 后续报错常是首错的结果，换工具链还会增加版本差异。 |
| 初稿完成后简查本次日志，处理编译错误、未定义引用或引文、重复标签等影响内容与导航的实际问题；缺字、索引拒收和重跑提示按影响处理。轻微 Overfull、Underfull、间距及分页问题留待后续审核，不为清除一般提示反复调整或重编。 | 初稿须能阅读和接续，但一般版面提示不值得挤占写作时间；严重错误与格式精修应区别处理。 |
| 结构与书签使用项目实际存在的检查脚本；说明其输入与覆盖范围，不把缺失清单、未运行或未支持的检查写成通过。 | 工具只能证明其实际检查的内容，不能代替未做的核验。 |
| 初稿阶段以源码和日志为常规依据，仅在绘制复杂图片、交换图等确需辨认空间或箭头关系时，按需查看对应 PDF 页面；普通插图、正文、表格和断行不例行渲染或截图审核，用户另有明确要求时按要求执行。 | 图片审核耗时较多，普通版面已有源码与日志可查，后续还有至少两轮外部审核；复杂图示的可辨认性才需要当前定向确认。 |
| 成品核验确认 PDF 来自当前源码；本次没有编译时如实说明，不能用旧 PDF 证明新改动有效。 | 文件存在和最新改动已经进入成品是两个不同事实。 |
| 旧工具故障的规避方法仅在当前环境满足其症状与适用条件时使用，条件消失即取消相应绕行。 | 旧版本的偶发问题不能成为永久增加步骤的依据。 |

当前单卷编译入口为：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Book 1
```

结构检查与已生成 PDF 的书签检查入口为：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Check-Outline.ps1
python -B .\scripts\Check-PdfBookmarks.py
```

两个检查入口均支持 `-Book 1` 选择单卷；所需运行环境和功能说明见[项目说明](../README.md)。以上是命令示例，验证范围按本节相应原因确定。

## 5. 工作记录的用途与取舍

| 规则 | 原因 |
|---|---|
| 所有工作记录都应能回答后续接续、定位、核验或决策中的具体问题；没有这类用途的操作过程直接在当次回复中交代。 | 工作记录的价值是降低下次工作的成本，记录活动本身没有独立价值。 |
| 保留记录前先明确其读者会查什么；只保留当前结论、相关位置、关键依据、未解决问题及确有必要的下一步。 | 必要信息能直接帮助接续，冗长过程会掩盖它们。 |
| 优先更新已有的主管记录，不为每轮修改另建报告、台账、里程碑或重复备份。 | 同一事实只有一个当前入口，才容易查阅和维护。 |
| [审核进度](../工作记录/审核进度.md)只维护当前完成度、正式审核及明确审稿结论，不追加逐日修改、逐项修订回顾、编译页数和校验值。 | 后续安排需要当前状态，而不是按时间重建一次结论。 |
| 审稿修改细节只在确有复核价值时保留于原意见或相关问题位置，不再抄入多份记录。 | 同一问题的依据集中后更易回查，也避免重复版本不一致。 |
| 已解决的问题若不再影响后续判断，不继续累加为长期记录；仍有复用价值的解决办法压缩到症状、适用条件、处理和结果。 | 可复用结论值得保留，已经失去用途的过程不值得长期维护。 |
| 临时统计、截图、渲染、构建日志及一次性脚本放在 `tmp/`；用途结束后可清理已核实的可重建产物，不把它们转成工作流水账。 | 临时证据有即时用途，但并不因此成为永久资料。 |
| 清理前核实路径和内容，只删除已确认的临时或可重建文件，不批量清理源码、用户修改、研究资料或未知文件。 | 这些材料可能无法恢复，清理便利不构成删除它们的理由。 |
| 记录用途或依据失效时及时合并、缩减或移除相应内容；无法判断是否仍有后续价值时先保留原材料并说明具体疑点。 | 记录也受总则约束，但其效用不明不等于可以不可逆地丢弃资料。 |

## 6. 本地修改与版本操作

| 规则 | 原因 |
|---|---|
| 日常只在本地编辑和核验；提交、上传、发布按用户的明确要求执行。 | 一次编辑任务或过去的一次上传授权不等于永久自动发布授权。 |
| 提交前核对实际差异与本次范围，只纳入相关源码、说明和必要成品。 | 工作区可能同时有用户或其他任务的修改。 |
| 不提交临时缓存、凭据和第三方参考全文；本地专用归档继续按忽略规则保存。 | 这些文件可能可重建、含敏感信息或没有重新分发依据。 |
| 推送前核对目标仓库与分支，推送后核对实际远端结果；非快进冲突先查差异，不强制覆盖。 | 本地成功不等于到达正确远端，强制操作可能丢失他人的工作。 |

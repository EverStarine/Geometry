# 《几何学》书目数据库维护注意事项

本文件规定 `Shared/References.bib` 的入库资格、版本、字段和正文引文定位。共同适用的规则效力见[总则](写作规范.md#总则)。数据库使用 `biblatex + biber`；证明责任与资料登记分别见[《写作规范》](写作规范.md)和[《工作流程说明》](工作流程说明.md)。

## 1. 适用范围与入库边界

| 规则 | 原因 |
|---|---|
| `Shared/References.bib` 只收录依据本文件核定、确实用于本书的参考文献，不作为内部资料库存；尚未核定的讲义、草稿、网络快照和扫描件按《工作流程说明》留在内部资料目录。 | 正式书目是交付给读者的可核查引用集合，若兼作资料库存，会把“已经取得”误写成“可以正式引用”。 |
| 正式 Bib 原则上只收入已经正式发表且满足年限的资料：论文自正式发表满三年，书籍所引版次自正式出版满五年；以核验当日为基准。不能用作品初版的旧年份为实质修订的新版放行，未改内容的普通重印须另说明其与原版次的关系。只有年份且处于临界年的条目，须核清出版日期后再判定；例外由作者明确指定，不因 PDF 可得而自动豁免。 | 作者当前以正式发表和一定使用时间限定公开参考书目范围；准确区分版次与日期才能落实这一选择。年限本身仍不能替代版本、内容和适用条件的核验。 |
| 下载、复制和保留的 PDF 不受上述年限限制，可以包括较新教材、预印本、作者讲义与草稿；在资料目录中注明实际版本、完整性、用途和查阅范围，未获准的材料不因此进入正式 Bib。 | 内部学习资料与向读者正式著录承担不同职责；新资料可以帮助写作，但文件存在或写作时间较早并不构成正式发表。 |
| 采集时优先核对出版社、期刊、DOI 注册机构、作者或机构官方网站；详细下载、版本登记、阅读范围、文件完整性和哈希流程统一执行《工作流程说明》。 | 权威来源能降低元数据误配风险；操作流程保留在单一主管文件可避免规则漂移。 |
| 正式入库仍不等于已经核读数学内容；实际引用前必须核对所引版本、论断、假设和位置。 | 元数据真实只说明文献身份可靠，不能保证正文对其结论或证明的转述正确。 |

## 2. 版本身份与证据

| 规则 | 原因 |
|---|---|
| 每条记录只描述一个确定的实体版本；`date`、`edition`、`publisher`、`series`、`volume`、`isbn` 等字段不得从不同版本拼接。 | 混用版本会制造现实中不存在的书目实体，并使页码、定理编号和载体标识无法核对。 |
| 应区分作品原始年份、实际引用版次年份与重印年份；必要时用 `origdate` 记录原版或该版首次出版时间，以 `date` 记录实际引用版本的出版或重印时间。 | 当前数据库统一使用 BibLaTeX 的日期字段；区分两类日期才能准确还原正文依据和实际分页。 |
| 有正式发表版本时按正式版本著录；作者稿或机构存档只作为取得全文的途径，不把作者稿日期当作正式出版年，也不把作者稿本身冒充正式版本。 | 取得载体与引用版本是两个不同事实，混淆二者会造成发表状态和定位信息错误。 |
| 未载日期的讲义、缺版本页的扫描件及无法确认发表实体的文件，不猜测年份，也不把访问日期当出版日期；除按本文件入库规则逐项认定的例外外，不写入正式数据库。 | 猜测的日期会伪造资格与版本证据，访问日只能证明何时查看，不能证明何时出版。 |
| 动态 URL、后期补配的 DOI 或数据库条目页不能单独证明所用 PDF 的固定版本；发生日期、版次或提交号差异时，应先按工作流程核对实际使用文件，再修改记录。 | 同一地址可能替换内容，稳定标识也可能晚于作品产生；仅凭链接会把不同快照或载体误认成同一版本。 |

## 3. Entry type 与字段语义

| 规则 | 原因 |
|---|---|
| 按文献实体选择 entry type：专著用 `@book`，期刊论文用 `@article`，同一作者专著中的章节用 `@inbook`，编辑文集中的独立文章用 `@incollection`，多卷著作按实际引用方式使用 `@mvbook` 或分卷记录。持续更新的网站、未正式发表的讲义和草稿在当前范围内只入内部目录，不以 `@online` 或 `@misc` 绕过正式发表和年限条件；作者明确指定例外时，再记录可定位的版本或快照及 `urldate`。不得把非正式资料一概塞入 `@misc`。 | Entry type 决定合法字段和最终排版；类型含混会丢失作品层级，也会掩盖资料尚未达到正式引用资格的问题。 |
| 字段必须与 entry type 相容。例如普通 `@article` 使用 `journaltitle`、`volume`、`number`、`pages`、`doi` 等字段，不添加不适用的 `publisher`。 | BibLaTeX 按数据模型解释字段；字段错位即使暂时能编译，也可能在样式变化或校验时产生错误输出。 |
| 版次、丛书与卷号分别写入 `edition`、`series`、`volume` 等结构化字段，不塞入 `title`。 | 结构化数据可由不同书目样式稳定排序和格式化，也便于检查版本一致性。 |
| `author`、`editor`、译者、修订者及其他贡献角色应依据实际版本的题名页或权威记录区分，并优先使用 BibLaTeX 对应的结构化字段；不得把丛书主编、分卷主编和协作者一概写成作者。 | 贡献角色关系到署名真实性和书目排序，混写会错误归属作品责任。 |
| 机构作者须用双重大括号保护整体名称，如 `author = {{National Institute of Standards and Technology}}`；条目性质更适合时使用 `organization`。 | 否则 Biber 可能把机构名称按个人姓名拆分并倒置。 |
| `note` 只保存确需向读者显示且没有更合适结构化字段的书目信息；只有对后续识别版本或核验引用有用的内部说明才放在 `工作记录/参考资料目录.md`，确需随 Bib 保存但不打印的说明用 `annotation`；不逐次记录检索和编译过程。 | `note` 可能直接输出到成品；必要的内部信息集中维护可方便回查，重复操作过程则不能帮助识别文献。 |
| `keywords` 中已有的机器可读追踪键应保持格式稳定；它们只能用于筛选和追踪，不能使未合格资料获得入库资格。 | 已有标签只有在被实际工具或检索使用时才有维护价值；内部状态不能改变正式书目的内容边界。 |
| 标题中的 `&` 等特殊字符须按 TeX 语法转义；专名、缩写和数学符号按需要保护大小写，如 `{Kähler}`、`{Noether}`、`{Hodge}`。 | 不正确的转义会导致编译失败，缺少大小写保护则可能被书目样式错误改写。 |

## 4. 姓名与 citation key

| 规则 | 原因 |
|---|---|
| 书目中的作者姓名依据实际引用版本的发表署名著录；正文中的人物称谓依《术语规范》，两者不为形式统一而互相改写。 | 正文称谓服务于中文叙述，书目署名服务于版本识别，二者承担的证据职责不同。 |
| 已被正文引用的 citation key 原则上保持不变，即使 key 中的年份与核定后的元数据不完全一致；确需改名时，必须同时可靠地全局替换全部引用并验证。 | Citation key 是内部关联标识而非书目事实，随元数据改名容易造成漏引、断链和跨卷不一致。 |

## 5. DOI、ISBN、URL 与访问日期

| 规则 | 原因 |
|---|---|
| 正式论文优先记录 DOI；有 `doi = {10....}` 时不再把同一个 DOI resolver 地址重复写入 `url`。 | DOI 已提供稳定身份与链接，重复字段会产生冗余输出，且可能被样式排成两个相同入口。 |
| 没有 DOI 的专著优先记录与实际引用版本和载体一致的 ISBN；须区分精装、平装、电子版等载体，无法确认时宁可暂不填。 | 不同载体可能对应不同年份、分页和版本，错误 ISBN 比缺失 ISBN 更会误导检索。 |
| 公开书目的 `url` 只保留具有独立阅读价值的链接，例如可合法直接阅读或明确下载全文的作者页、机构库或持续更新的在线参考资料；商品页、普通数据库条目页和仅用于核验元数据的页面不写入 `url`。已有 DOI 或 ISBN 时，全文 URL 也只有在增加开放阅读价值时才并存。 | `url` 会作为读者入口公开显示，筛去中介页和易失效商品页可提高可用性并减少维护负担。 |
| 动态在线资源使用 `urldate` 记录实际访问日期，并在适用的 `version`、`date` 或必要的 `note` 字段及 URL 中给出读者可识别的版本、修订日期或固定快照；有固定 DOI 的正式论文或专著通常不记录 DOI resolver 的访问日期。 | 访问时间说明内部核验发生于何时，可定位的内容版本才使读者能够复查；稳定出版物的 resolver 访问时间没有书目辨识价值。 |

## 6. 正文定位后注

| 规则 | 原因 |
|---|---|
| 卷、章、节、定理、命题、定义、公式、段落码和页码等定位信息写在正文 `\cite[...]` 的后注中，不写入 `References.bib` 的 `note`。 | 定位信息取决于本次引用的具体用途；写入共享条目会让所有引用错误地显示同一定位。 |
| 每个定位后注必须回到实际引用版本核对题名、结构名称、环境类型、大小写、编号次序和页码；来源只给段落码时保留段落码，不自行改称定理或命题。核验不足时降低到已确认的层级，或删去推荐，不猜编号。 | 不同版次和来源的结构可能变化，擅自标准化会把读者导向错误位置。 |
| 外文资料保留原文结构类型和编号，中文原版或实际引用的中译本保留中文；例如原书的 `Section 2`、`§3`、`Chapter VI` 不擅自翻译成另一类结构。大小写可按本书后注样式统一，只要不影响检索。 | 定位后注的首要目标是让读者在实际版本中找到目标；结构类型和编号具有辨识价值，纯大小写则不必机械复制。 |
| 针对特定主题的阅读建议应给出可直接查找的章、节、定理编号，或在没有编号时给出原文题名与页码；整编导读可给章级范围，章首和局部专题应尽量定位到对应的节。不得以“相关章节”“有关内容”或单列书名代替定位。 | 阅读建议只有达到与主题相称的精度，才真正帮助读者查找材料并允许后续复核。 |
| 特定证明方法、特殊版本、外部结果、反例和历史归属应在相应陈述附近给出针对性引文；本书已经完整证明的标准结果不必在每次调用时重复引文。 | 引文应说明实际外部依赖，而不是按名词出现频率堆叠，也不能让外部来源与本书证明责任混淆。 |
| 后注使用半角标点：`, ` 分隔同组信息，`; ` 分隔独立定位组；半角逗号后保留一个空格，外文定位不擅自改写成中文“第……节／定理／命题”。 | 统一标点可避免中西文混排和断行异常，也防止格式改写掩盖未经来源支持的结构名称。 |

## 7. 成品书目的输出规则

| 规则 | 原因 |
|---|---|
| `urldate` 保留在数据库供内部核验，五卷成品及全量测试书目统一隐藏访问日期；不得连带隐藏出版年份、版次、内容版本、修订日期、固定快照、DOI、ISBN 或有阅读价值的 URL。动态资料须先满足上文的可定位版本要求，不能以隐藏访问日期掩盖版本不明。 | 已有可定位版本时，逐条显示访问日不能增加内容辨识信息；读者实际找回所引版本所需的信息则必须保留。 |

## 8. 验证与修改范围

| 规则 | 原因 |
|---|---|
| 新增或修改 Bib 条目后，在 `tmp/` 下运行 Biber 工具模式，同时启用 `--validate-datamodel` 与 `--dieondatamodel`，并把输出文件和日志显式导向临时目录；随后按项目流程重编实际引用该条目的卷。 | 默认工具模式会在当前目录生成新 Bib 和日志，且数据模型问题通常只给警告；临时输出与失败即停止可同时避免污染工作区和漏过错误。 |
| 批量修改数据库或调整书目输出样式后，另建最小测试文档，以 `\nocite{*}` 排出全部条目，检查作者与机构解析、中文和特殊字符、版次、DOI、ISBN、URL、`note`、访问日期隐藏及链接输出。正式五卷仍只打印各自实际引用的条目，不保留 `\nocite{*}`。 | 全量测试能发现尚未被当前五卷正文引用的坏记录，同时避免把测试手段误带入成品书目。 |
| 修改 citation key 或正文定位后注后，搜索全部引用并重编受影响卷；检查未定义引文、Biber 警告、链接目标、后注标点与断行。 | 这些改动同时影响数据库关联和正文呈现，仅检查 Bib 文件不能发现漏替换或排版问题。 |

## 9. 筹备期的书目与 PDF

| 规则 | 原因 |
|---|---|
| 按作者要求为后续写作建立参考书库时，可以预先收入已核定出版身份、符合年限并与纲要有明确对应的正式条目；不自动把纲要中的人名、资料代号或前作书目转成条目，也不使用 `\nocite{*}` 将筹备书库印入各卷成品。 | 筹备期需要可复用的正式书目信息，但选作参考不等于已经引用，更不等于已核读其中的证明。 |
| 资料目录分别说明正式出版物的书目身份与手头 PDF 的实际身份；作者修订稿、出版前稿、节选或前置页不能冒充已著录版次的完整正式文本。未取得全文的核心书目明确标示，正文引用页码和结果前再核对实际版本。 | 正式元数据和可读文件不一定对应同一文本，分清二者才能避免错引页码或把内容缺失当作资料齐备。 |
